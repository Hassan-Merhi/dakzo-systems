# Authority & Marketing System — Wave 5

## Phase 19 — Authority and backlinks

Dakzo Systems should earn references from real relationships and real work. The site now provides a canonical `/brand/` resource that partners, directories, project websites, and press can use for verified company facts, official logos, case-study links, and attribution guidance.

### Approved authority sources

- Dakik LLC corporate properties
- client/project websites where Dakzo genuinely developed or maintains the technology
- partner and integration pages
- reputable software, technology, startup, and business directories
- genuine press/news coverage
- GitHub and engineering profiles controlled by Dakzo Systems
- case-study collaborations

### Prohibited tactics

- purchased bulk backlinks
- fake offices or local listings
- fabricated testimonials, awards, clients, partnerships, or social profiles
- automated directory spam
- keyword-stuffed anchor text
- reciprocal-link schemes created only to manipulate rankings

### Preferred attribution

`Technology platform developed by Dakzo Systems — A Dakik LLC Company.`

Where possible, link a project reference directly to the relevant case study rather than only the homepage.

## Phase 20 — Social and brand presence

The website is the canonical identity source. External profiles are linked only after the company controls and verifies them. Recommended rollout order:

1. LinkedIn company page
2. GitHub organization/profile
3. YouTube for product demos and technical explainers
4. Instagram for visual product/brand storytelling if actively maintained
5. Other channels only when there is a clear audience and publishing cadence

Each verified profile should use the same company name, logo, short description, website URL, and Dakik LLC relationship.

## Phase 21 — Portfolio visual system

Wave 5 introduces original, lightweight SVG product visuals for HMD ERP, Congo Delivery, and Moto Track. They are illustrative product compositions, not fabricated screenshots. This avoids falsely presenting UI states while giving each case study a stronger visual identity.

Visual rules:

- 16:9 responsive compositions
- accessible title and description in SVG
- no third-party image dependencies
- no confidential customer data
- no fake performance metrics
- small file sizes suitable for the site's performance budget
- each visual must reflect the actual workflow category of its project

Future projects should receive an original visual under `site/assets/work-<slug>.svg` and expose it on both the Work index and project case study.
